# Nedra Digital PipeTwin

Демо-сайт с визуализацией данных: https://lliulliyjiuku.github.io/pipetwin-demo/

**Проверяющему:** откройте [PipeTwin_final.ipynb](PipeTwin_final.ipynb) и выполните все ячейки сверху вниз. Ноутбук читает шесть исходных CSV из `data/`, выполняет предобработку, обучает две выбранные модели и сохраняет **`result_case1.csv` и `result_case2.csv`**. Старые эксперименты и заранее обученные веса для запуска не нужны.

[Локальный запуск](#локальный-запуск) · [Google Colab](#google-colab) · [Выходные файлы](#выходные-файлы) · [Предобработка и допущения](#предобработка-и-допущения)

## Что воспроизводится

| Кейс | Целевая труба, `id` | Дата прогноза | Сегментов | Итоговая модель |
| --- | --- | --- | ---: | --- |
| 1 — с предыдущим обследованием | `1250022871` | `2023-12-01` | 525 | CatBoost + Transformer |
| 2 — без собственной истории обследований | `1250009583` | `2022-07-01` | 1475 | LSTM + дополнительные признаки + PCA + Ridge |

Модели и гиперпараметры выбраны в ходе экспериментов с Optuna. В финальном ноутбуке они зафиксированы: повторный поиск гиперпараметров не запускается. Для второго кейса применяется также фиксированная ручная корректировка, описанная ниже.

По уточнению ментора результаты передаются **двумя отдельными CSV — по одному на каждый кейс**.

## Локальный запуск

### 1. Установите зависимости

Рекомендуемая среда — **Python 3.11, 64 bit**. Версия указана в `.python-version`; сам интерпретатор этот файл не устанавливает.

Распакуйте проект или скачайте репозиторий. Откройте **PowerShell в корне проекта**, рядом с `requirements.txt`, и выполните:

~~~powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m ipykernel install --sys-prefix --name pipetwin --display-name "Python (PipeTwin)"
.\.venv\Scripts\python.exe -m jupyterlab
~~~

Активация окружения для этих команд не требуется. Интернет нужен для установки библиотек; предобученные модели ноутбук не скачивает.

Для Linux/macOS команды аналогичны:

~~~bash
python3.11 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m ipykernel install --sys-prefix --name pipetwin --display-name "Python (PipeTwin)"
~~~

1. В открывшемся JupyterLab откройте `PipeTwin_final.ipynb`.
2. Выберите ядро **Python (PipeTwin)**.

## CUDA, seed и параметры запуска

В начале ноутбука находится единый словарь `FINAL_CFG`.

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `project_dir` | `None` | Корень проекта; по умолчанию текущая рабочая папка |
| `seed` | `42` | Фиксированный seed выбранного решения |
| `prefer_cuda` | `True` | Использовать доступную CUDA для нейросетей и GPU для CatBoost |
| `allow_cpu_fallback` | `True` | Перейти на CPU при недоступности GPU или обрабатываемой ошибке CUDA |
| `threads` | До 4 | Число потоков CPU |
| `run_validation` | `True` | Дополнительно обучить модели на фолдах и сравнить с базовыми подходами |
| `run_temporal_control` | `True` | Выполнить дополнительную временную проверку первого кейса |
| `make_rankings` | `True` | Сохранить ранжирование сегментов и верхние 10% |
| `make_diagnostic_intervals` | `False` | Построить диагностические интервалы по остаткам валидации |
| `case2_multiplier` | `1.15` | Зафиксированная ручная корректировка второго кейса |
| `case2_lower_fraction` | `3.5 / 4.5` | Нижняя граница доли остаточной толщины второго кейса |

**GPU не обязателен.** PyTorch и CatBoost проверяют доступность устройств отдельно; Ridge выполняется на CPU. Выбранные устройства печатаются в начале и записываются в артефакты обучения. Для CUDA нужна совместимая с драйвером сборка PyTorch **2.7.1**; варианты установки приведены в разделе v2.7.1 [официальной инструкции PyTorch](https://pytorch.org/get-started/previous-versions/).

Для получения двух итоговых CSV без повторной валидации измените в исходном словаре только `run_validation` и `run_temporal_control` на `False`. Итоговые модели всё равно будут обучены на всех подготовленных обучающих данных. Основные CSV записываются до дополнительных блоков.

Seed `42` фиксируется для Python, NumPy и PyTorch. Версии библиотек и конфигурация сохраняются для каждого запуска. Численные результаты могут немного различаться между CPU/GPU, версиями драйверов и оборудования; фиксированный seed не гарантирует побайтовое совпадение на любых устройствах.

## Этапы решения

1. **Чтение и аудит.** Загрузка шести CSV, разбор чисел и дат, контроль повторов и сохранение контрольных сумм исходников.
2. **Предобработка и сегментация.** Сопоставление измерений с паспортом, проверка толщины и координат, построение полной сетки 10-метровых сегментов, подготовка рельефа и истории режима.
3. **Создание признаков и меток.** Паспорт, положение сегмента, рельеф, доступные предыдущие измерения, агрегаты режима и показатели полноты данных. Метка — минимальная допустимая измеренная толщина в сегменте на дату обследования. Для кейса 2 собственная история ВТД/УЗТ исключена из входов.
4. **Обучение двух выбранных моделей.** Transformer и LSTM кодируют историю режима; полученные признаки объединяются с табличными. В кейсе 1 прогноз строит CatBoost. В кейсе 2 применяются дополнительные признаки, масштабирование, PCA и регрессия Ridge с последующим переводом доли толщины в миллиметры.
5. **Экспорт и проверки.** Применение фиксированной выходной политики, создание отдельных CSV, проверка покрытия сегментов, пропусков и дублей.
6. **Дополнительная оценка.** Валидация по целым участкам, базовые решения, графики, ранжирование и, при включении соответствующего параметра, диагностические интервалы.

Все этапы реализованы внутри `PipeTwin_final.ipynb`. Параметры моделей и обработчиков сохранены в его коде.

## Предобработка и допущения

- **Пропуски сохраняют смысл отсутствия наблюдения.** Неизмеренная толщина не заменяется номинальной и не становится обучающей меткой. Сегменты без метки исключаются из обучения, но присутствуют в полной сетке прогноза.
- **Измеренные толщины и метки не сглаживаются.** Внутри сегмента используется минимум допустимых измерений; он зависит от плотности обследования и не равен гарантированному минимуму по всей поверхности трубы.
- **Толщина проверяется относительно паспорта.** Допустимый диапазон — `(0, nominal_mm]` с техническим epsilon, допуск превышения номинала — `0 мм`. В данной поставке все 67 строк УЗТ не проходят это правило и не используются как достоверные толщины. Это принятое правило очистки; производственные допуски отдельно не моделируются.
- **Глубина дефекта не исправляет явно ошибочную толщину.** Толщина восстанавливается из глубины только при отсутствии исходной толщины и подтверждённом масштабе глубины. Противоречия фиксируются в аудите.
- **Измерения сопоставляются с локальной координатой участка.** Учитывается смещение `accumulated_value`; координаты за пределами паспортной длины исключаются. Точная конечная точка относится к последнему сегменту.
- **Точные дубликаты удаляются из аналитических копий.** Исходные файлы не переписываются. Текстовые заглушки «нет данных» заменяются пропуском; содержательные категории вроде «Нет» сохраняются.
- **Время ограничивает доступную информацию.** Измерения до ввода трубы в эксплуатацию исключаются. История признаков обрезается по установленному временному cutoff; сведения после него не используются. Доступные обучающие метки должны предшествовать дате прогноза.
- **Поля целевого обследования не входят в признаки.** Показатель `pit_corrosion_intensity` также исключён из-за неподтверждённого происхождения.
- **Режим не восстанавливается через многолетние пробелы.** Дневные значения агрегируются медианой. Варианты интерполяции коротких внутренних пропусков выбираются внутри обучения; длинные интервалы и непокрытая история остаются неизвестными. Нейросетевой кодировщик использует наблюдения, маски пропусков и показатели покрытия.
- **Аномалии режима различаются по смыслу.** Нулевой расход может означать остановку и сохраняется. Некорректные физические значения обрабатываются с флагами качества; спорные сочетания давления и расхода отмечаются отдельно. Неподтверждённые единицы не переводятся произвольно.
- **Паспорт считается исторически постоянным**, поскольку история изменений его полей отсутствует. Обработка числовых пропусков, категорий, отбор признаков и PCA обучаются на обучающей части соответствующего разбиения.

Причины исключений и проверки записываются в `processed/audit/` внутри каталога запуска.

### Выходная политика моделей

Для кейса 1 прогноз ограничивается диапазоном от 0 до паспортной номинальной толщины — 8 мм для целевой трубы.

Для кейса 2 модель обучается предсказывать долю номинальной толщины. После перевода в миллиметры применяется фиксированный множитель `1.15` и ограничение доли диапазоном `[3.5 / 4.5, 1]`. Для текущей целевой трубы с номиналом 4.5 мм это эквивалентно:

~~~text
thickness_pred = clip(1.15 × raw_prediction_mm, 3.5, 4.5)
~~~

Корректировка выбрана вручную в ходе разработки с учётом полученной обратной связи. Она не является параметром, найденным Optuna, или физическим законом коррозии. Прогноз второго кейса имеет малый разброс вдоль трубы: хорошая MAE сама по себе не подтверждает качество локализации опасных сегментов.

## Валидация и метрики

Используются три разбиения с исключением целого `id` участка из обучения. Соседние сегменты одного участка не распределяются случайно между train и validation. Дополнительно предусмотрена временная проверка первого кейса.

Выбранные модели сравниваются с доступными для кейса базовыми решениями: номинальной толщиной, медианной долей толщины, предыдущим измерением и линейной экстраполяцией потери толщины.

Основные показатели:

- **MAE, мм** — средняя абсолютная ошибка; меньше — лучше.
- **`Pearson_r2`** — квадрат коэффициента корреляции Пирсона, метрика задания.
- **RMSE, мм**, знаковая корреляция Пирсона и коэффициент детерминации **`R2`** — дополнительные диагностические метрики.
- **`MAE_macro_mm`** — средняя MAE по участкам, чтобы большой участок не определял всю оценку.

`Pearson_r2` отличается от коэффициента детерминации `R2` (`sklearn.metrics.r2_score`). Для постоянного прогноза корреляция математически не определена; такие случаи код обрабатывает явно.

Разбиения и параметры уже использовались при выборе решения. Эта OOF-оценка повторяет проверку этапа разработки и не является независимым финальным тестом. Для изменившегося состава обучающих данных воспроизведение прежней OOF-проверки может быть пропущено с объяснением в `validation_status.json`.

~~~csv

~~~

`id` — идентификатор трубы; `segment_id` — номер 10-метрового сегмента, начиная с 0; `thickness_pred` — прогноз толщины в миллиметрах. Разделитель колонок — запятая, десятичный разделитель — точка; индекс DataFrame не записывается.

| Файл | Строк данных | Значения `segment_id` |
| --- | ---: | --- |
| `result_case1.csv` | 525 | `0…524` |
| `result_case2.csv` | 1475 | `0…1474` |

Проверки в ноутбуке контролируют отсутствие пропусков, повторов ключа `(id, segment_id)` и лишних/недостающих сегментов. Их итог записывается в `solution_checks.json`. Контрольные суммы файлов запуска находятся в `final_manifest.csv`.

Интервалы при `make_diagnostic_intervals=True` строятся по остаткам OOF. Это диагностические полосы, а не гарантированно откалиброванный доверительный интервал.

Папки `.venv/` и `final_runs/` исключены из Git через `.gitignore`. Для проверки кода достаточно ноутбука, зависимостей и исходных данных; два готовых CSV для сдачи нужно взять из нужного завершённого запуска отдельно.

## Если запуск остановился

| Ситуация | Что сделать |
| --- | --- |
| `Не найдена папка data` или не найден конкретный CSV | Проверьте имена шести файлов и `FINAL_CFG["project_dir"]`; в Colab ожидается папка `/content/data/` при `"project_dir": "/content"` |
| `ModuleNotFoundError` / сообщение о неустановленных библиотеках | Локально установите `requirements.txt` в выбранное ядро `Python (PipeTwin)`; в Colab проверьте, что используется подготовленная среда с библиотеками |
| CUDA недоступна | Оставьте `allow_cpu_fallback=True` для запуска на CPU; выбранные устройства будут напечатаны |
| Дополнительный блок завершился ошибкой | Проверьте, успели ли сохраниться основные CSV в напечатанном каталоге; для повторного получения только прогнозов отключите `run_validation` и `run_temporal_control` и начните новый полный запуск |
